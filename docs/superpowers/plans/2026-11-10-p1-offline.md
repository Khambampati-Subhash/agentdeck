# P1: No Link to herdr.dev Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AgentOS (app and core) never contacts herdr.dev. It never downloads, updates, installs, fetches media or sends telemetry or feedback there.

**Architecture:** Upstream already routes every network use through an override
(`HERDR_RELEASES_URL`, `HERDR_TELEMETRY_URL`, `HERDR_FEEDBACK_URL`) and falls back
to a herdr.dev default. We delete the defaults: with no server configured, each
feature is off and says so. Tests keep pointing the overrides at local servers. A
repo script fails the build if a herdr.dev URL reappears in code.

**Tech Stack:** Rust (app: GPUI; core: tokio), sh/PowerShell installers, Python unittest (`app/scripts/test_distribution.py`), just.

**Spec:** `docs/plan.md` § P1, `CLAUDE.md` § Rules ("Never talk to herdr.dev").

## Global Constraints

- No URL containing `herdr.dev` may be used to make a request by any code that ships, whether a build from source or a release build.
- An override set to the empty string counts as unset.
- Keep upstream mergeable: change only the lines that pick a URL and their callers. Don't rename anything (P2 does that), and don't touch the `HERDR_APP_RELEASE` semantics.
- Don't change licence text, `CHANGELOG.md` history or links to `github.com/herdrdev`.
- Tests run in scratch homes and sessions only (`CLAUDE.md`); no real agents.
- Commit messages: lowercase conventional, `app:`/`core:`/`repo:` prefix, ending with the
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` line.

## Review Focus

1. `HERDR_RELEASES_URL=""`: must behave as unset in app and core, never request `/core/latest.json` with no host (T2, T5).
2. An app home copied from a real Herdr install with `update-notes-cache.md` holding `media.herdr.dev` links must still fetch nothing (T2: the gate is on the fetch, not on the notes source).
3. `HERDR_TELEMETRY_URL=""` and `HERDR_FEEDBACK_URL=""` must send nothing, even in a release build (T3).
4. `machine add --install` for a machine of another CPU, with no release server: a clear `unavailable` error, nothing half-installed there (T5).
5. With `core` unset in settings, the app finds the user's upstream `~/.local/bin/herdr-core`. P1 must not let `app.update_core` or "Install it for me" download anything for it (T2, T4). Isolation from that core is P2.
